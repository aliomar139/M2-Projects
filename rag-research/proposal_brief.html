Master's Research Proposal : Systems and Retrieval Efficiency

Cascaded Adaptive Blended RAG: A Systems Extension for Efficient Multi-Field Hybrid Retrieval

Base Paper: Sawarkar et al. (IEEE MIPR 2024)
Core Focus: Pre-Retrieval Early Exit for Hybrid RAG
Target Hardware: Laptop and CPU Reproducible
01 Base Paper Foundation and the Latency Bottleneck
What Blended RAG showed: Sawarkar et al. (IBM Research, 2024) proved that blending dense vector embeddings, learned sparse representations (SPLADE), and BM25 across document fields (title, abstract, text) significantly beats single-retriever systems. On standard benchmarks, it achieved 68% F1 on SQuAD, 42% Exact Match on NQ, and 88.8% retrieval accuracy on NQ without task-specific fine-tuning.
The Static Hybrid Penalty RESEARCH PROBLEM
Blended RAG runs all three retrieval models (Dense vector index, Sparse SPLADE model, and BM25 lexical index) for 100% of incoming queries. For simple factual queries where keywords already identify the right passage, running expensive neural vector search is redundant compute. Easy queries pay the exact same 30 to 80 ms latency penalty as complex multi-hop queries.
02 Proposed Systems Extension: Cascaded Blended RAG
Defensible Systems Positioning
We frame this work directly as the first adaptive systems extension of Blended RAG. We do not claim to invent adaptive RAG as a general concept. Instead, we remove Blended RAG's static execution bottleneck using a fast sequential cascade while preserving its multi-field metadata design.
Concrete Efficiency Targets
35–50% Faster · ≥ 96% Acc.
Bypasses neural vector search on 40% to 60% of queries via BM25 early exit, while maintaining ≥ 96% of static Blended RAG Recall@10, MRR, and downstream QA generation scores.
03 Architectural Specification: The Four Technical Pillars
Tier 0: Feature Check < 1 ms (CPU)
Pre-Retrieval Specificity Check
Extracts lexical specificity directly from query text before index lookup: query length, maximum inverse document frequency (MaxIDF), and rare token ratio.
Tier 1: BM25 Fast-Pass 2 to 5 ms (CPU)
Confidence Margin Early Exit
Runs fast lexical search. If top score s₁ ≥ τ_high or score margin Δ = s₁ − s₂ ≥ τ_gap, halts and returns candidates immediately. Skips 100% of neural vector compute.
Tier 2: Blended Fallback 30 to 80 ms
3-Way Hybrid Fusion (RRF)
When lexical confidence is low (Δ < τ_gap), escalates to full Blended RAG: Dense MiniLM-L6 + SPLADE sparse term expansion + BM25, merged via Reciprocal Rank Fusion.
Cross-Tier: Metadata Zero Extra Overhead
Best Fields Matching
Applies Blended RAG's core method: searching across structured fields (title, abstract, text) so scientific corpora like SciFact retain high precision across both tiers.
Sequential Decision Rule Route(Q) = BM25_Exit IF [s₁ ≥ τ_high] OR [Δ ≥ τ_gap AND MaxIDF(Q) ≥ τ_idf], ELSE Tier2_BlendedRAG

Experimental Protocol and Baselines
  • Datasets: BEIR SciFact (5,183 scientific papers, 300 test queries) and Natural Questions (NQ) subset for direct comparison with Sawarkar et al.
  • Baselines: (1) Pure BM25, (2) Dense MiniLM-L6, (3) Sparse SPLADE, (4) Static Blended RAG, (5) Adaptive Baselines (Adaptive-RAG and DAT).
  • System Metrics: Mean and tail latency (P50, P90, P99 ms), and percentage of neural vector searches avoided.
  • Quality Metrics: Recall@5, Recall@10, MRR@10, nDCG@10, plus Exact Match and F1 using a local 3B generator.
Risk Management and Backup Plan
  • Handling router errors (Wu & You, 2026): Adaptive routers can misclassify ambiguous queries. We calibrate conservative thresholds (τ_gap, τ_high) via 5-fold cross-validation.
  • Backup plan 1: If early exit drops recall by over 2%, pivot the router to dynamic alpha weighting for 3-way Blended RRF.
  • Backup plan 2: Shift to adaptive top-k depth truncation for Blended RAG (following SAGE and CAR).
  • Defense value: Mapping the exact boundary where lexical confidence works provides direct systems value for production RAG.
